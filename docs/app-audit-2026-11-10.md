# App audit, 10 November 2026

What was measured, what was wrong and why, what changed, and what is still open. Rows 1 to 16 of
"Fixed" are in pull request #131 (merged); rows 17 to 25 are in #132. Each has tests that were
checked by breaking the code on purpose and confirming a test fails. Everything in "Open" is not
done.

## How the app was measured

Three things were measured before anything was changed, so each fix has a before and an after.

1. **Every page at two sizes.** A script opened each route on a 390x844 phone and a 1280x800
   desktop, saved a full-page screenshot and counted headings, buttons, inputs and page height.
2. **Every guided tour at three sizes.** A script walked all 8 guides (47 steps) at 320x568,
   390x844 and 1280x800 and recorded, for each step, whether the target was found, whether it was
   on screen, and whether the card covered it.
3. **The code.** Import graph (which files nothing imports), bundle contents by package, complexity
   caps, the Worker's routes and their checks, and every place a transition or scroll is animated.

## Open

Nothing here is a defect a person would run into today. Each is a decision, or a check that could
not be made from here.

| What | Why it matters | Recommendation |
|---|---|---|
| Sign-in and sign-up may have two page titles | Their form is drawn by the sign-in provider, which does not load in the test environment, so its heading level was not checked | Open the sign-in page with a screen reader's heading list once; if the form has its own first-level heading, the fix is one word on two routes |
| Budget shows twenty help buttons before anything is entered | Each is a 44 px keyboard stop. They now have different names (row 23) and each carries guidance its label does not | Keep them. Folding them into one "how this works" per section would hide the guidance that is specific to a field |
| The old Express server in `server/` | Not deployed; still linted and tested in CI. Billing, the report page and the admin console are written against it | Keep it until those three move to the Worker. Removing it now means removing those screens too |
| `firebase.json` and `vercel.json` | Hosting configuration for two services the app is not deployed to; `README.md`, `docs/DEPLOYMENT.md` and `docs/PRODUCTION_DEPLOYMENT.md` describe them as options | If Cloudflare and GitHub Pages are the only hosts, remove both files and those sections together |
| `Claude_changes.md` (107 kB), `social-snapshot.md`, `memory/`, `scripts/batch-*.ts`, `scripts/agent-validate.ts` | Working notes and one-off agent scripts at the top of the repository. No build or test reads them | Yours to keep or delete. If kept, `docs/` is a better home for the notes |
| React is held at 18.2.0 | It was held there for React Native, which is gone (row 22) | Move to 18.3 as its own change with a full test run |
| The language file is fetched after the app's code has started, not alongside it | One more request before the first screen on a first visit. ## Things checked and found sound

- The Worker scopes every query to the signed-in person, uses bound parameters everywhere, checks
  the token's authorised party, and answers only the allowed origins.
- The Express routes that still exist sit behind `requireAuth` and rate limits.
- No `dangerouslySetInnerHTML`, no `any`, no `@ts-ignore`, no `TODO` in `src`.
- Both languages have the same keys (the build fails otherwise).

## What research says about apps built this way

- A study of 200 deployed AI-built apps (arXiv 2606.23130) found at least one vulnerability in 90%
  of them: broken access control in 36%, secrets or weak cryptography in 21%, injection in 18%. The
  causes it names are security rules that were never written down, design aimed at a demo, a control
  loosened to make something work, and a change made in one place but not the others.
- The last cause is the one this audit kept finding, in product behaviour instead of security: the
  motion setting honoured in 3 places out of 30, a tour target present in one view out of three, an
  empty state written for a layout that later changed. The fixes above each replace many copies
  with one (one attribute, one toggle component, one heading component), with a test that fails if
  a copy comes back.
- A second pattern is specific to this stack: a limit written in the wrong unit. The sync
  service's body limit counted characters, not bytes (row 15). Cloudflare D1 has its own limits
  (100 bound parameters per query; 50 queries per request on the free plan); the Worker's writes
  stay under both today, and a much larger sync payload is the case to watch.
- Sources: arXiv 2606.23130; Invicti's report on secrets in AI-generated code; Cloudflare's D1
  limits page.

## Trade-offs made

- **The graph and animation libraries were removed, not loaded on demand.** A routine's steps are a
  straight sequence; a plain list shows that. If branching routines are ever built, a graph comes
  back then.
- **A guide no longer pulls you back to its tab.** Open another tab mid-step and you stay there; the
  card stays on screen with Next and Back. The old behaviour is what caused the address loop.
- **The Social guide is hidden on plans without Social.** It walked through a locked screen.
- **Daily view is a switch among the preferences**, not a section of its own with a button.
- **Empty sections are hidden, not explained.** Someone new to Calendar sees the grid and "Add
  event" and nothing about focus suggestions until they have a task to suggest. The guide and the
  page introduction still describe them.
- **Four help buttons on Budget were removed** (period, and a transaction's amount, date and notes).
  Their text repeated the label or the heading's own help.
- **Opening Pricing, Privacy or Terms now takes one more request** the first time (30 kB for the
  legal page). The installed app caches all of them, so they still open offline.
- **Analytics count what was shown, not only what was done.** A new `screen_state` event records
  whether Calendar and Routines were empty and whether Budget asked for a category or offered the
  transaction form; `setting_changed` records each Settings switch. Neither carries any text a
  person typed.
- **A guide's overview is ten steps, not nine.** The experiment that compares the long and short
  overview still calls the long one `overview9`, so links that force a variant keep working.
- **Spanish does not fall back to English.** A fallback would make every Spanish visit download the
  English text as well. The build already fails when a key is missing from either language.
- **Changing language can now fail**, when there is no connection and the service worker has not
  yet cached the other language. The app stays in the language it was in and says so; choosing
  again works once the connection is back. `language_changed` and `language_load_failed` are counted.
- **One screen is written in both languages in the code instead of the language files:** the page
  shown when the first language file cannot be fetched. The language file is the thing that did not
  arrive.
- **A help button's name now contains its label** ("Information: Add event" beside "Add event").
  Someone using voice control says the whole name, or "Information", to reach the help.
- **The Tasks screen counts whether its list was empty** (`screen_state`, as Calendar and Routines do).
