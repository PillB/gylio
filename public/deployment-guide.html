Start here: the mental model

ELI5: your VPS is a small computer that stays online. Nginx is the front desk. It gives visitors the built website and quietly sends anything beginning with /api to the Node server behind it. MongoDB Atlas stores shared data. Clerk proves who the user is.

Why this is the primary path: you already have a KVM 1, so serving both the static frontend and API from the same VPS keeps the first production deployment understandable and avoids an extra cross-origin hosting layer.

Read this before touching production

  • Billing is not live. Keep VITE_BILLING_ENABLED=false. The current repository intentionally treats checkout as a preview.
  • AI is optional. The core app works without an OpenAI key; the AI endpoint reports unavailable.
  • Clerk package drift: this repository still imports @clerk/clerk-react. Current Clerk React documentation uses @clerk/react. Do not “fix” that during infrastructure setup; migrate the SDK as a separately tested code change.
  • KVM 1 is a CLI server. Do not choose Hostinger's Remote Desktop image; Hostinger currently requires KVM 2 or higher for that image.
  • Never paste passwords, MongoDB URIs, Clerk secret keys or OpenAI keys into this guide. Only non-secret deployment labels below are stored in your browser.

Install Node 24 with nvm

Official nvm ↗

ELI5: Node is the engine. nvm is the engine selector, so the project can use the same major Node version locally and in CI.

Do this

Install nvm using its current official installer, reopen your terminal if needed, then install Node 24.

STEP 10 · BASIC SECURITY

Patch Ubuntu and enable the firewall without locking yourself out

Ubuntu firewall ↗

ELI5: the firewall is a door list. We explicitly keep SSH open first, then allow the web doors. Port 3001 stays off the public list.

Run in this exact order
sudo apt update
sudo apt upgrade -y
sudo apt install -y ufw curl git ca-certificates nginx
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
sudo ufw status verbose

Never add a UFW allow rule for port 3001 in this architecture. Nginx is the public front door.

Test: keep your current SSH session open, start a second SSH session, and run sudo ufw status.
Expected: OpenSSH + Nginx Full allowed; no 3001 rule.

STEP 24 · ROLLBACK

Practice returning to a known-good Git commit

Git switch ↗

ELI5: rollback means “put yesterday's known-good code back, rebuild it, and restart”—without deleting your database.

Emergency procedure

Troubleshooting by symptom

502 Bad Gateway

Nginx is alive but Node is not answering. Run:

pm2 status
pm2 logs gylio-api --lines 100
curl -i http://127.0.0.1:3001/api/health

Health says databaseReady:false

Check Atlas IP access, database user, URI and PM2 env:

pm2 env gylio-api
pm2 logs gylio-api --lines 100

Frontend works, login fails

Check production Clerk key, domain/DNS, issuer and CLERK_AUTHORIZED_PARTIES. Rebuild after changing a Vite variable.

Deep link gives 404

Nginx must keep try_files $uri $uri/ /index.html; in location /.

SSH stopped working

Use Hostinger Browser Terminal / console. Check UFW and SSH settings. This is why the guide tests a second SSH session before progressing.

Certificate command fails

First verify DNS resolves to this VPS and port 80 is reachable. Certbot cannot prove control of a hostname pointed elsewhere.
